# تثبّت — مدقق ذكي للرسائل الدينية المتداولة

مشروع مشارك في «تحدي الذكاء الاصطناعي في خدمة المحتوى الإسلامي» 2026، مسار أدوات المعرفة والتحقق.

**العرض الحي:** <https://tathabbat.vercel.app>

> **تنبيه:** «تثبّت» أداة ذكاء اصطناعي للمساعدة في التحقق من نسبة الروايات، **وليست مفتياً**. حكمها يخص الرواية (صحة نسبتها) لا العمل أو المسألة الفقهية، وأحكامها منقولة بنصها من كتب أئمة معتمدة لا مولَّدة من النموذج. للفتوى راجع جهة مؤهلة. ولم تُراجَع مواد الأداة مراجعة شرعية بشرية بعد (انظر «الحدود المعروفة»).

## ما هو تثبّت؟

تلصق فيه رسالة دينية وصلتك في واتساب أو تيليجرام، فيفكّكها إلى ادعاءات منفصلة ويتحقق من كل ادعاء في فهرس محلي لمتون كتب معتمدة، ثم يعرض لكل ادعاء: الحكم، والنص المنقول **حرفياً** من الكتاب مع موضعه ورابط للتحقق بنفسك، وردّاً مهذباً جاهزاً للمشاركة في المجموعة.

مبدأ العمل: **النموذج اللغوي (Gemini) لا يُصدر حكماً شرعياً ولا يكتب نصاً دينياً.** دوره استخراج الادعاءات واختيار المدخل المطابق من نتائج بحث جلبها الكود. أما النص المعروض فيقتطعه الكود حرفياً من المدخل المخزَّن ويتحقق برمجياً أنه جزء منه؛ فإن فشل التحقق يُخفَّض الحكم إلى «لم نجد» (امتناع). ولا يصدر حكم «صحيح» إلا عند مطابقة تامة مرتّبة للفظ في صحيحي البخاري ومسلم، أو في مدخل منتقى بحكم بشري.

الأحكام الممكنة: صحيح، ضعيف، موضوع، لا أصل له بحسب عالم (منقول)، مختلف فيه، منسوب لغير النبي ﷺ، اللفظ يختلف عمّا في المصدر (يعرض لفظ المصدر بلا حكم)، نص الإمام بلا تصنيف آلي، آية موثّقة أو محرّفة، إحالة لمتخصص (الفتوى والحالات الشخصية)، لم نجد له أصلاً في المصادر التي فُحصت (امتناع وليس حكماً شرعياً)، لم يُفحص (انتهى الوقت أو زاد العدد). التفصيل في صفحة «عن المنهجية» داخل الأداة.

## كيف يعمل (مختصر)

```
رسالة نصية (≤ 3000 حرف)
  1. استخراج الادعاءات وتصنيفها (نداء Gemini واحد؛ حتى 6 ادعاءات تُفحص)
  2. لكل ادعاء، بالتوازي:
       فتوى أو حالة شخصية      ← إحالة لمتخصص، بلا بحث ولا حكم
       آية                     ← مطابقة محلية مع نص Tanzil (بلا شبكة)
       غير ذلك                 ← بحث في الفهرس المحلي (MiniSearch، تطبيع عربي، أفضل 10) ← «المنتقى» البشري يسبق
                               ← Gemini يختار المرشح فقط
                               ← الكود: مطابقة اللفظ المرتّبة + اقتطاع النص حرفياً
                               ← تحقق برمجي: المصدر ضمن النتائج والنص جزء حرفي منه، وإلا «لم نجد»
  3. تقرير لكل ادعاء + رد جاهز للمشاركة (يتضمن تنبيه الذكاء الاصطناعي)
```

الفهرس المحلي مبني وقت البناء من: صحيح البخاري (7125 مدخلاً) وصحيح مسلم (3167) و«المقاصد الحسنة» للسخاوي (1355)، مع 48 مدخلاً منتقى بحكم بشري. لا اتصال بأي موقع مصادر وقت التشغيل. تفاصيل المصادر والتراخيص في [`SOURCES.md`](SOURCES.md).

## التشغيل محلياً، خطوة بخطوة

المتطلبات: Node.js 22.x ومفتاح Gemini API.

```bash
git clone https://github.com/7ussienk/tathabbat.git
cd tathabbat
npm install
cp .env.example .env        # ثم ضع GEMINI_API_KEY (وGEMINI_MODEL إن أردت غير الافتراضي) في .env
npm run fetch-books         # يجلب متون الكتب الثلاثة (نحو 23MB) إلى data/local/ (خارج Git)
npm run build-index         # يقطّع المداخل ويبني الفهرس في data/index/ (خارج Git)
npm run dev                 # الواجهة على http://localhost:3000
npm test                    # اختبارات الوحدة (بمزوّد وهمي، بلا نداءات Gemini)
```

للإنتاج: `npm run build` ينفّذ الجلب ثم بناء الفهرس ثم `next build`، والمستودع جاهز للنشر على Vercel بإضافة متغيرات البيئة أدناه.

### حدود إعادة بناء الفهرس
- متون الكتب **لا تُرفع إلى Git**؛ تُجلب وقت البناء من `files.turath.io/books-v3/{id}.json`، وهو **مسار غير موثق وقد يتغير** (ومسار `turath-sdk` القديم صار يعيد 404).
- الجلب طلب واحد في كل مرة مع مهلة وإعادة محاولة، وتخزين في ذاكرة البناء. ويتحقق من شكل الملف (عدد الصفحات المتوقع، و1355 مدخلاً للمقاصد) **ويفشل البناء بوضوح إن اختلف**، فلا يُنشر فهرس ناقص بصمت.
- «المقاصد الحسنة»: 1355 هو **عدد المداخل** لا آخر رقم؛ الأرقام المطبوعة تمتد إلى 1356 والرقم 406 غير موجود في الطبعة.
- مدخلات مسلم التي بلغت حد 4 صفحات للمدخل (509 مدخلاً) نصها مقطوع عند الحد.

## متغيرات البيئة

أسماء فقط (القيم في بيئة التشغيل ولا تُرفع إلى Git). النموذج الأساسي والاحتياطي لهما افتراضيان في الكود.

| المتغير | الاستخدام |
|---|---|
| `GEMINI_API_KEY` | **مطلوب.** مفتاح Gemini API |
| `GEMINI_MODEL` | النموذج الأساسي (الافتراضي `gemini-3.8-flash`) |
| `GEMINI_FALLBACK_MODEL` | نموذج احتياطي عند تعثّر الأساسي (الافتراضي `gemini-3.7-flash`) |
| `VERIFY_API_TOKEN` | توكن المسار الآلي `/api/machine/verify` (للتقييم والاستدعاء الآلي؛ بدونه يُرفض المسار) |
| `CONFIDENCE_THRESHOLD` | عتبة الثقة (الافتراضي 0.75) |
| `RATE_LIMIT_PER_MIN`, `IP_DAILY_CAP`, `DAILY_CAP` | سقوف الطلبات (لكل IP في الدقيقة، لكل IP يومياً، إجمالي يومياً) |
| `COST_DAILY_CAP_USD`, `MACHINE_COST_DAILY_CAP_USD` | سقف التكلفة اليومي التقديري للمسار العام والآلي |
| `VERIFY_DISABLED` | `1` = وضع صيانة بلا أي نداء نموذج (يحتاج Redeploy) |
| `OVERALL_TIMEOUT_MS`, `LLM_FIRST_TIMEOUT_MS`, `LLM_FALLBACK_TIMEOUT_MS` | مهل المعالجة والنداءات |
| `PRICE_IN_PER_M`, `PRICE_OUT_PER_M` | أسعار التوكنز لتقدير التكلفة |
| `EVAL_MAX_USD` | سقف تكلفة مشغّل التقييم (الافتراضي 0.5$) |

يحتوي `.env.example` أيضاً على `GEMINI_FILE_SEARCH_STORE` و`TELEGRAM_BOT_TOKEN` و`TELEGRAM_WEBHOOK_SECRET`، وهي **غير مستخدمة في هذه النسخة**.

## نتائج التقييم

**قراءة الأرقام:** كلها من تشغيلات مسجَّلة يوم 4 أكتوبر 2026، وليست من تشغيل واحد على الكود النهائي:
- **المجموعة المستقلة:** التشغيل الحي الوحيد، ثم إعادة حساب من كاش نتائج النموذج (بلا نداءات جديدة) على الكود المجمَّد الموسوم `text-phase-freeze` بلا أي تغيير في المنطق. إصداراتها الأخيرة: المعجم `lexicon-2026-10-04.4`، البرومتات `prompts-2026-10-04.5`، التسجيل `scoring-2026-10-04.3`.
- **مجموعة التطوير:** أُجري التشغيل الرسمي المعتمد (ثلاث تشغيلات) بالمعجم .3 والتسجيل .2، ثم عُدّل المعجم إلى .4 والتسجيل إلى .3؛ وصحة التعديلين فُحصت بتشغيل مستهدف وبإعادة حساب 225 حالة من الكاش (صفر تغيّر)، وليست بتقييم كامل جديد.
- لم يُجرَ تقييم كامل نهائي (ثلاث تشغيلات × نمطان) على الكود المجمَّد نفسه، وتقرير `eval/report.md` في المستودع من تشغيل أقدم موسوم فيه بأنه غير نهائي.

التفاصيل والجداول الكاملة: [`docs/PHASE1_RESULTS.md`](docs/PHASE1_RESULTS.md).

### مجموعة التحقق المستقلة (26 حالة، وُسمت قبل التشغيل ولم يُضبط عليها شيء)
المجموعة نفسها خاصة وغير منشورة (حتى لا تُضبط عليها الأداة). **وسمها المطوّر بمساعدة مساعد ذكاء اصطناعي من قراءة عبارة الإمام في كل مدخل، وهي ليست حكماً شرعياً ولم يراجعها متخصص.** كل الحالات خدمها `gemini-3.7-flash` لأن 3.8 كان متعثّراً وقتها، وبدون `data/curated`، وبتشغيل واحد.

| | الإصابة | ملاحظة |
|---|---|---|
| كما شُغّلت (معجم .3) | **12/26 (46.2%)** | التشغيل الحي الوحيد |
| بعد تصحيح الوسم | **14/26 (53.8%)** | أُضيف `authentic` إلى المقبول في حالتين (V001 وV019) **بعد** التشغيل: الحديثان بلفظهما في الصحيحين وكان الوسم الأول على مدخل «المقاصد» وحده |
| بعد إصلاح المعجم (.4) | **16/26 (61.5%)** | حالتان (V010 وV013) أُصلح المعجم **بعد رؤيتهما** فهما غير مستقلتين؛ **الـ16 ليست دقة مستقلة** |

اختلاق المصدر في هذه المجموعة: **0**. **هذه الأرقام أقل من هدف 90%**، وسببها الغالب أن معجم الأحكام الثابت لا يصنّف صيغاً كثيرة من ألفاظ الأئمة فتخرج «نص الإمام بلا تصنيف آلي» (نقل صحيح للنص لا حكم مصنَّف)، وأن المستخرِج يهمل عبارات مجردة (أقوال مأثورة أو أمثال أو أدعية) أُرسلت بلا إسناد. أنماط الإخفاق في [`docs/KNOWN_LIMITS.md`](docs/KNOWN_LIMITS.md).

### مجموعة اختبار الألفاظ المعدَّلة (منفصلة عن الـ89 رسالة)
ملف مستقل `eval/wording_altered.jsonl`: **98 حالة اصطناعية** (للتقييم فقط، لا تدخل البيانات المنتقاة ولا العرض)، منها 87 حرجة، في أربع فئات: **48** حديثاً معدَّل اللفظ (تبديل أو حذف أو استبدال أو زيادة، 12 مرساة × 4 أنواع)، و**24** ضابطاً بلفظ الحديث كما في المصدر (المتوقع «صحيح»)، و**15** ادعاءً مضاداً (يجب ألا يصدر لها `wording_differs`)، و**11** جزءاً من حديث. هي مجموعة أنشأها المطوّر بعد اكتشاف خلل في مطابقة اللفظ، فهي **ليست مستقلة** عن الإصلاح.

## الحدود المعروفة

القائمة الكاملة وما بعد التحدي: [`docs/KNOWN_LIMITS.md`](docs/KNOWN_LIMITS.md). أهمها:

- **تغطية الفهرس ثلاثة كتب فقط** من قائمة بيضاء أوسع. لذلك «لم نجد له أصلاً» تعني «لم نجده فيما فُحص» وليست حكماً شرعياً، وتُعرض معها قائمة الكتب المفحوصة.
- **لا مراجعة شرعية بشرية بعد:** كل مدخلات `data/curated` موسومة «بانتظار مراجعة شرعية»، والتحقق الآلي من مطابقة النص للمصدر لا يغني عنها.
- **المعجم الثابت محدود:** صيغ مثل «لا أعرفه» و«لا يثبت» و«ليس في المرفوع» تخرج «نص الإمام بلا تصنيف آلي».
- **الأداة قد تعرض لفظاً مختلفاً عمّا في المصدر ولا تحكم بخطئه** (`wording_differs`)؛ فالعبارة القصيرة (ثلاث كلمات أو أربع) تطابق مواضع كثيرة فنعرض أقرب ثلاثة ولا نحكم.
- **المستخرِج** قد يهمل دعاءً أو مثلاً مجرداً أُرسل بلا إسناد، وقد لا يرى ادعاءً في عبارة من كلمة أو كلمتين.
- **حدود الطلب:** نص فقط، حتى 3000 حرف، وتُفحص أول 6 ادعاءات والباقي يظهر بحكم «لم يُفحص».
- **حدود التشغيل:** عدّادات الحماية وقاطع الدائرة في ذاكرة كل نسخة تشغيل (تقريبية)، وتعثّر `gemini-3.8-flash` يرفع الزمن ويُخفَّف بالنموذج الاحتياطي.
- الاعتماد على مسار جلب غير موثق (انظر «حدود إعادة بناء الفهرس»).

## الخصوصية

- **لا تُحفظ نصوص الرسائل** ولا أي ملف: لا في قاعدة بيانات ولا في السجلات. السجلات حقول تقنية فقط من قائمة سماح ثابتة (المدة، عدد الادعاءات، الأحكام، عدد التوكنز والتكلفة، حالة الطلب)، وأي حقل خارجها يُهمل.
- لا يُستنتج شيء عن المستخدم، ولا حسابات ولا تتبّع.
- **لتحليل الرسالة يُرسل نصها (أو المقطع الصوتي لاستخراج نصه) إلى Gemini API (Google)** بوضع `store:false`، وتخضع معالجته لشروط Google. لا تُدخل معلومات شخصية في الرسالة.
- تحديد المعدل يعدّ الطلبات لكل IP في الذاكرة فقط لمدة الدقيقة أو اليوم، دون حفظ دائم.

## ما تغيّر عن ملف الفكرة

- **بوت تيليجرام خارج هذه النسخة.**
- **الصوت:** الصوت متاح بنمط «استخراج النص ثم التحقق»: زر «صوت» يتيح **رفع ملف أو تسجيلاً مباشراً** (حتى 30 ثانية و2MB)، فيستخرج النص ويضعه في مربع الرسالة لتراجعه وتصحّحه، ولا يبدأ التحقق إلا بضغط «تثبّت». **المجرَّب فعلاً: iPhone 15 Pro (تسجيل مباشر وتفريغ وتحقق)، و`.opus` من واتساب، وwebm/opus من Chrome.** ما عدا ذلك غير مجرَّب.
- **الصورة مؤجلة لما بعد التحدي.**
- المصدر وقت التشغيل **فهرس محلي** مبني وقت البناء من ثلاثة كتب (لا Gemini File Search ولا اتصال حي بالمكتبة الشاملة)، فتغطيته أضيق من القائمة البيضاء الكاملة.
- الدرر السنية: رابط تحقق خارجي فقط، لا أحكام منها ولا نسخ لبياناتها.
- **مجموعة الاختبار 89 رسالة نصية بدل 100، دون فئة الرسائل الصوتية.**
- **لم يُجرَ إثبات الإضافة بالمقارنة مع أداة قائمة.**
- **لم تحصل مراجعة متخصص شرعي** (القائمة المعدّة للمراجعة لم تُسلَّم).

## بنية المستودع

`app/` الواجهة ومسارات الواجهة البرمجية (`/api/verify`، `/api/transcribe`، `/api/machine/verify`، `/api/health`) · `lib/pipeline/` خطوات المعالجة · `lib/retrieval/` الفهرس والتقطيع · `lib/llm/` مزود Gemini · `data/curated/` المدخلات المنتقاة · `data/quran/` نص القرآن · `data/sources/manifest.json` سجل المصادر · `eval/` مجموعة الاختبار ومشغّل التقييم · `docs/` القرارات والحدود والنتائج · `tests/` اختبارات الوحدة.

## نسبة نص القرآن
نص القرآن الكريم المستخدم في التحقق من الآيات هو **Tanzil Quran Text (Uthmani, v1.1)** من مشروع [Tanzil](https://tanzil.net)، بترخيص Creative Commons Attribution 3.0، ويُستخدم حرفياً دون أي تعديل (الملف: `data/quran/quran-uthmani.txt`).

## ملفات الصوت لا تُنشر
مجلد `eval/audio/` مستثنى من Git (تسجيلات شخصية والمستودع عام). لا توجد حالات صوتية في مجموعة التقييم الحالية، ولم يُقِس التقييم الآلي دقة استخراج الصوت.
